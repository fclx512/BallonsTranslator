### 2026-09-09 — 上游 v1.5.13 → v1.5.15 吸收批次

**背景：** 用户审查卡片页后指出「单供应商切模型体验不如上游」，并要求顺带评估上游最近版本的改动。调研窗口 v1.5.13..v1.5.15（dev = 1.5.15，本地克隆原只到 1.5.13，本次 fetch 补齐）。用户定取向：**底层性能/实现优先服从上游**（不自造轮子），显性功能按需求取舍。

**上游模型切换机制（`ballontranslator/ui/llm_profile_widgets.py` + `ballontranslator/utils/llm_profiles.py`）：**

- 每个 profile 持久化 `model_options` / `vision_model_options` / `image_model_options`，`PROVIDER_DEFAULTS` 给每个供应商预置 2~11 个模型名，`_merge_profile_options` 把「内置 + 已保存 + 当前值」合并去重；
- 摘要行常驻模型下拉（`ProfileCardWidget` 的 summary grid，`ParamComboBox` + `+`/`−` 就地增删），展开前就能切；
- 底部模块栏 `ballontranslator/ui/module_tool_button.py::ModuleSelectionWidget._buildProfileMenu` 按分区列出各 profile 的模型清单，点一下同时切 profile + 模型；
- **上游没有 Fetch Models**（全文搜过），靠预置清单 + 手填覆盖离线切换。

**fork 采纳与偏差：** 吸收「清单 + 摘要行下拉 + 手填增删」，但**不预置供应商模型表**（用户拍板：清单只由 Fetch Models 或手填产生）；保留并升级 fork 的 Fetch Models 为多选添加（`utils/profile_manager.py::FilterableListDialog` 的 `multi_select`），网络只用于刷新清单。底部模块栏模型子菜单未做（fork 用模块参数里的 `active_profile` 而非上游的 `pcfg.module.*_llm_id`，留待后续）。
